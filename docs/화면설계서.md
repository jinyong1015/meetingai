| SCR-02 Step 1 새 회의 생성 | **구현** | `/meetings/new`. `[회의 시작]` 시에만 로컬 저장 |
| SCR-02 Step 2 녹음·메모 | **대부분 구현** | MediaRecorder·음성 감지 웨이브(VAD)·권한 UX·메모. 조각 저장·원본 재생은 미완 |
| SCR-02 종료 후 STT | **구현** | 녹음 종료 → Pre-recorded 전사 → **음성 인식 결과** 패널. Realtime 없음 |

| SCR-03·04·06 | 미구현 | LLM·검토·웹훅 |

### STT 처리 규칙 (현재)

- 녹음 **중**에는 실시간 전사를 하지 않는다. **입력 레벨 웨이브만** 표시하며, 웨이브는 **실제 음성이 감지될 때만** 움직인다(무음·주변 소음에서는 평평).
- 녹음 **종료** 후 전체 음성 파일을 선택한 STT 엔진으로 전사한다.
- AssemblyAI는 **Pre-recorded** (`/v2/upload`, `/v2/transcript`, `universal-2`, `ko`)만 사용한다.
- Whisper는 `WHISPER_API_URL`이 설정된 로컬(또는 호환) 엔드포인트로 전송한다.
- API 키는 `.env.local` 서버 환경변수에만 두고, 설정 UI에는 설정 여부만 표시한다.

### 입력 웨이브 규칙 (REC-03, 현재)

- `useMicAnalyser`가 `AnalyserNode`로 RMS·주파수 대역을 샘플링한다.
- 적응형 노이즈 게이트로 음성 활동(`voiceActive`)을 판별한다.
- `AudioWaveform`은 `voiceActive`일 때만 바 높이를 변경한다. 일시정지·무음에서는 평평한 상태를 유지한다.
- 이는 **입력 확인용 UI**이며 STT·Realtime 전사와 무관하다.

### 저장 시점 규칙 (SCR-02)

- `/meetings/new`를 열기만 하고 `[취소]` 또는 `← 회의 목록`으로 나가면 **회의를 생성하지 않는다.**
- `[회의 시작]`을 누르면 IndexedDB `meetings`에 저장한 뒤 `/meetings/{meetingId}/record`로 이동한다.
- 제목 미입력(공백 포함)은 `새 회의 YYYY-MM-DD HH:mm`으로 저장한다.
- 전사 결과는 IndexedDB `transcripts`(회의당 1건)에 저장하며 새로고침 후에도 복원한다.

## 6.8 Acceptance Criteria

### SCR01-AC01

새 회의 버튼을 선택하면 SCR-02 생성 화면(`/meetings/new`)으로 이동한다. 이 시점에는 아직 녹음이 시작되지 않으며, `[회의 시작]` 전까지 회의가 목록에 저장되지 않는다.

### SCR01-AC02

회의 목록 기본 정렬은 회의 일시 기준 최신순이다.

### SCR01-AC03

검색·기간·상태 필터를 동시에 적용할 수 있다.

### SCR01-AC04

회의 삭제 후 해당 회의가 목록에 남아 있으면 안 된다.

### SCR01-AC05

회의 1,000건 기준 목록 조회·검색 P95 목표는 500ms 이하이다.

# 7. SCR-02 새 회의 / 녹음

## 7.1 화면 목적

사용자가 최소한의 회의 정보를 입력한 후 즉시 녹음을 시작할 수 있도록 한다.

### 권장 Route

새 회의:

```text
/meetings/new
```

생성 후:

```text
/meetings/{meetingId}/record
```

---

# 7.2 Step 1 — 새 회의 생성

이 화면은 **작성 중 초안을 IndexedDB에 미리 만들지 않는다.**  
`[회의 시작]`을 누르기 전에 `[취소]` 또는 `← 회의 목록`으로 나가면 SCR-01에 회의가 추가되지 않는다.

```text
┌───────────────────────────────────────────────┐
│ ← 회의 목록                                  │
│                                               │
│ 새 회의                                      │
│                                               │
│ 회의 제목                                    │
│ [_______________________________________]     │
│                                               │
│ 회의 일시                                    │
│ [ 2026.09.10 ] [ 14:00 ]                     │
│                                               │
│ 참석자                       선택 사항        │
│ [ 김OO, 이OO___________________________ ]     │
│                                               │
│ 태그                          선택 사항       │
│ [ + 태그 추가 ]                              │
│                                               │
│                      [취소]    [회의 시작]    │
└───────────────────────────────────────────────┘
```

`[회의 시작]` 성공 시:

1. 회의 기본 정보를 IndexedDB `meetings`에 저장한다.
2. `/meetings/{meetingId}/record`로 이동한다.
3. 자동으로 녹음을 시작하지 않는다.

저장 실패 시 입력값을 유지하고 재시도한다. 중복 클릭해도 회의는 1건만 생성한다.

# 7.5.1 녹음 종료 후 — 음성 인식 결과

녹음 종료 시 MediaRecorder로 수집한 전체 음성을 설정한 STT로 전사한다. 변환이 끝나면 메모 영역 위에 결과 패널을 표시한다.


- 새 녹음을 시작하면 이전 전사 결과는 초기화된다

```text

OpenAI

[음성만 저장]             [AI 회의록 생성]
```

`AI 회의록 생성`

→ 체크박스가 선택된 경우 SCR-03 이동.

미선택 시 버튼 비활성화.

# 7.11 Acceptance Criteria

### SCR02-AC01

마이크 권한이 없는 상태에서 녹음이 시작되어서는 안 된다.

### SCR02-AC02

녹음 시작 버튼의 연속 클릭으로 두 개 이상의 Recorder가 만들어지면 안 된다.

### SCR02-AC03

녹음 중 생성된 메모에 녹음 시점이 기록되어야 한다.

### SCR02-AC04

일시정지 시간은 실제 녹음 길이에 포함되지 않는다. 녹음 중 입력 웨이브는 실제 음성이 감지될 때만 움직이고, 무음에서는 평평해야 한다.

### SCR02-AC05

AI 처리 확인 없이 선택한 클라우드 STT·LLM으로 데이터가 전송되어서는 안 된다. Whisper·Ollama만 선택된 경우에도 확인 없이 처리를 시작해서는 안 된다.

### SCR02-AC06

`/meetings/new`에서 `[회의 시작]` 전에 목록·취소로 나가면 회의가 IndexedDB·목록에 남지 않는다. `[회의 시작]` 성공 후에만 목록에 나타나며, 중복 클릭해도 1건만 생성된다.

# 10.4 AI 엔진

STT와 LLM을 각각 선택한다. 선택값은 재실행 후에도 유지되며, AI 생성 실행·동의 안내에 반영된다.

```text
AI 엔진

MeetingAI
├── STT
│   ├── Whisper
│   └── AssemblyAI
└── LLM
    ├── Ollama
    └── OpenAI

STT (음성 → 텍스트)
( ) Whisper        로컬 · 음성을 이 기기(또는 로컬 서버)에서 전사
(•) AssemblyAI     클라우드 Pre-recorded · 녹음 종료 후 음성을 외부로 전송

연결 상태
Whisper      ● 로컬 사용 가능 / ! WHISPER_API_URL 미설정
AssemblyAI   ● 설정됨 · 서버 환경변수 확인됨 / ! ASSEMBLYAI_API_KEY 미설정

                               [저장]
```

실제 API 키·엔드포인트 비밀값은 표시하지 않는다. 연결 불가·미설정 엔진을 선택한 채 저장하면 오류를 표시하고 저장하지 않는다.
현재 구현은 **STT 선택만** 제공한다. LLM 선택·프롬프트·일반 설정 탭은 예정이다.

# 10.12 Acceptance Criteria

### SCR05-AC01

요약 프롬프트와 상세 회의록 프롬프트를 독립적으로 저장할 수 있다.

### SCR05-AC02

프롬프트가 20자 미만 또는 4,000자 초과일 경우 저장할 수 없다.

### SCR05-AC03

화면에 실제 API Secret이 표시되어서는 안 된다.

### SCR05-AC04

저장하지 않은 프롬프트·엔진 변경이 있는 상태에서 Dialog 종료 시 경고해야 한다.

### SCR05-AC05

STT는 Whisper 또는 AssemblyAI, LLM은 Ollama 또는 OpenAI 중 하나를 선택·저장할 수 있으며, AI 동의·처리 화면에 선택값이 반영되어야 한다.

### SCR05-AC06

연결 불가 엔진을 선택한 상태에서는 AI 생성을 시작할 수 없다.

# 13. 접근성

모든 화면은 다음 기준을 따른다.

모든 주요 버튼은 키보드로 접근 가능.

Modal을 열면 Focus가 Modal 내부로 이동한다.

처럼 문자와 함께 표시한다.

### Error


처럼 구체적으로 안내한다.

# 18. MVP Definition of Done

MVP는 다음 조건을 모두 만족해야 완료된 것으로 판단한다.

1. 사용자가 새 회의를 생성할 수 있다.
2. 브라우저 마이크를 이용해 회의를 녹음할 수 있다.
3. 녹음 중 메모를 작성할 수 있다.
4. 음성과 메모가 로컬에 안전하게 저장된다.
5. 사용자가 AI 처리(및 클라우드 사용 시 외부 전송) 여부를 명시적으로 확인한다.
6. 선택한 STT(Whisper 또는 AssemblyAI Pre-recorded)로 **녹음 종료 후** 음성이 한국어 텍스트로 변환된다. (Realtime Streaming은 P2)
7. 선택한 LLM(Ollama 또는 OpenAI)이 요약 및 상세 회의록을 생성한다.
8. 결정사항과 후속 업무의 근거를 원문에서 확인할 수 있다.
9. 사용자가 AI 결과를 수정할 수 있다.
10. AI 원본과 사용자 수정본이 구분되어 보존된다.
11. 사용자가 회의록을 확정할 수 있다.
12. 재생성이나 복원으로 기존 확정본이 사라지지 않는다.
13. 회의 데이터를 검색할 수 있다.
14. 회의 데이터를 백업·복원할 수 있다.
15. 확정본을 웹훅으로 외부 시스템에 전송할 수 있다.
16. API Key가 클라이언트에 노출되지 않는다.
17. 네트워크 또는 AI 서비스 오류가 발생해도 기존 정상 데이터가 손상되지 않는다.
18. P0 Acceptance Criteria와 QA 필수 테스트가 모두 통과한다.

# 19. 핵심 UX 원칙

### 1. 녹음을 방해하지 않는다.

녹음 중 사용자가 해야 하는 조작은 최소화한다.

### 2. 저장 상태를 숨기지 않는다.

사용자는 자신의 음성과 메모가 저장되고 있는지 항상 알 수 있어야 한다.

### 3. AI를 사실의 원본으로 취급하지 않는다.

AI 결과는 항상 검토 가능한 초안으로 제공한다.

### 4. AI 결과에 근거를 제공한다.

결정사항과 후속 업무는 가능한 경우 음성 또는 전사 위치와 연결한다.

### 5. 중요한 결과를 덮어쓰지 않는다.

AI 재생성, 사용자 수정, 버전 복원은 모두 기존 결과를 보호하는 방식으로 동작한다.

### 6. 외부 전송을 사용자가 이해할 수 있게 한다.

‘로컬 저장’과 ‘AI 처리용 외부 전송’을 명확하게 구분한다.

### 7. 실패도 하나의 정상적인 UI 상태로 설계한다.

네트워크 오류, 전사 오류, AI 오류, 저장 실패, 웹훅 실패를 각각 별도 상태로 처리한다.

# 20. 제품 개발 기준

이 프로젝트에서 좋은 UX는 단순히 화면이 깔끔한 것을 의미하지 않는다.

사용자가 다음 질문에 언제나 답을 알 수 있어야 한다.

**지금 녹음되고 있는가?**

**내 데이터가 저장되었는가?**

**AI가 지금 무엇을 처리하고 있는가?**

**이 내용은 AI가 만든 것인가, 내가 수정한 것인가?**

**AI가 이 결론을 어디에서 가져왔는가?**

**이 회의록은 확정되었는가?**

**외부 시스템으로 어떤 정보가 전송되었는가?**

이 질문에 화면 자체가 명확하게 답할 수 있을 때 AI 회의록 서비스의 UX가 완성된 것으로 판단한다.
