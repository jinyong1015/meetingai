문서에 제시한 시간·용량·품질 수치는 **MVP의 제안 요구사항과 검증 목표**이며, 이미 달성한 성능이나 외부 AI 제공업체의 보장 수준을 의미하지 않는다. MVP는 핵심 가치를 검증하기 위한 최소 기능 제품을 뜻한다.

## 1. 제품 개요

### 1.1 목적: 해결하려는 문제와 제공 가치

회의록 작성자는 회의에 참여하면서 동시에 발언을 기록해야 한다. 회의가 끝난 뒤에는 메모와 기억을 바탕으로 내용을 재구성하고, 결정사항과 담당 업무를 다시 정리해야 한다.

본 제품은 이러한 작업을 자동화하되, **AI가 만든 내용을 사용자가 확인할 수 있는 근거와 수정 기능을 함께 제공**한다.

| 사용자 문제 | 제품의 해결 방식 | 기대하는 사용자 가치 |
|---|---|---|
| 발언을 기록하느라 회의에 집중하기 어렵다. | 회의 음성을 녹음하고 종료 후 자동으로 전사한다. | 회의 참여와 의사결정에 집중한다. |
| 회의 후 메모를 다시 정리하는 데 시간이 든다. | 핵심 요약과 안건별 상세 회의록을 각각 생성한다. | 회의 후 문서 작성 시간을 줄인다. |
| 결정사항·담당자·기한을 놓친다. | 결정사항과 후속 업무를 별도 항목으로 추출한다. | 실행할 업무를 명확하게 확인한다. |
| 과거 회의 내용을 찾기 어렵다. | 회의별 저장, 검색, 날짜·상태 필터를 제공한다. | 필요한 정보를 다시 찾는 시간을 줄인다. |
| 다른 업무 시스템에 내용을 다시 입력한다. | 확정된 회의록을 웹훅으로 전송한다. | 반복 입력을 줄인다. |

**제품 원칙:** AI 결과는 처음부터 ‘확정된 사실’이 아니라 **검토 가능한 초안**으로 제공한다. 결정사항과 담당 업무는 가능한 한 원문 위치를 함께 표시한다.

### 1.2 초기 제품 범위

| 구분 | MVP 포함 범위 | MVP 제외 범위 |
|---|---|---|
| 서비스 형태 | PC 브라우저에서 사용하는 웹 앱 | 모바일 네이티브 앱 |
| 사용자 | 개인 1명, 개인별 독립 데이터 | 조직 계정, 권한 관리, 공동 편집 |
| 실행 환경 | 개인 전용 Next.js Node.js 인스턴스. 기본 배포는 사용자 PC의 로컬 실행 | 인증 없이 인터넷에 공개하는 배포 |
| 지원 브라우저 | 출시 시점 Chrome·Edge의 최신 및 직전 주요 버전 | Safari·Firefox·모바일 녹음 공식 지원 |
| 녹음 대상 | 사용자가 선택한 마이크 입력 | 회의 봇, Zoom·Teams 자동 입장, 시스템·탭 오디오 직접 캡처 |
| 언어 | 한국어 전사 및 한국어 결과 생성 | 실시간 통역, 다국어 번역 |
| AI 처리 시점 | 녹음 종료 후 처리 | 실시간 자막·실시간 요약 |
| 저장 | 동일 브라우저·프로필·서비스 주소의 로컬 저장소 | 클라우드 동기화, 기기 간 자동 동기화 |
| 외부 연동 | 등록된 수신처에 JSON 웹훅 발송 | 모든 협업 도구의 전용 연동 |
| 결과 관리 | 조회, 수정, 재생성, 버전 보존, 확정, 내보내기 | 전자결재, 법적 전자서명 |

마이크 녹음만으로 다른 프로그램이나 원격 참석자의 음성이 직접 수집되는 것은 아니다. 따라서 녹음 화면에는 **“선택한 마이크로 입력되는 소리만 녹음됩니다”**를 표시한다. 브라우저 마이크 접근에는 사용자 권한과 보안 실행 환경이 필요하며, 구현은 `getUserMedia()`를 사용한다. 

**로컬 저장의 의미**

회의 데이터의 제품 내 보관 위치는 로컬이다. AI 처리는 설정의 **STT·LLM 엔진 선택**에 따라 로컬 또는 외부 서비스를 사용한다.

```text
MeetingAI
├── STT (음성→텍스트)
│   ├── Whisper     … 로컬 전사
│   └── AssemblyAI  … 클라우드 전사
└── LLM (요약·상세 회의록)
    ├── Ollama      … 로컬 생성
    └── OpenAI      … 클라우드 생성
```

AssemblyAI를 선택하면 음성이 외부로, OpenAI를 선택하면 전사문·선택한 메모가 외부로 전송된다. Whisper·Ollama만 사용하는 경우에는 해당 단계의 외부 전송이 없다. 따라서 **‘로컬 저장’과 ‘외부 전송 없음’을 동일하게 안내해서는 안 되며**, 실제 선택 엔진에 맞춰 전송 대상을 안내한다. 클라우드 제공업체의 데이터 보관 정책도 별도로 적용된다. 

### 1.3 대상 사용자

| 결정사항·후속 업무 추출 재현율 | 90% 이상 | 사람이 작성한 정답 목록 중 AI가 정확히 추출한 항목 비율 |

사용 지표는 기본적으로 로컬에 저장한다. 시험 운영 중 지표를 수집할 때에도 회의 본문을 자동 전송하지 않고, 사용자가 동의한 집계 정보만 수집한다.

## 2. 기능 명세

### 2.0 공통 규칙과 우선순위

**P0는 출시 필수, P1은 후속 개선, P2는 확장 기능**이다. 기존 요구사항 ID와 의미를 유지하며, 아래 기능은 별도로 표시하지 않는 한 P0로 정의한다. 화면 ID는 구현 단위, 요구사항 ID는 기능·품질 계약, AC ID는 화면에서 확인할 인수 기준으로 구분한다.

| 우선순위 | 적용 범위 | 출시 판단 |
|---|---|---|
| P0 | REC-01~07, NOTE-01~05, DATA-01~07, AI-01~12, SET-01~08, WH-01~07, NFR-01~07, SEC-01~08 및 SCR-01~06의 필수 흐름 | 7장의 필수 검증·출시 차단 기준 적용. 웹훅은 기본 꺼짐이어도 구현·검증은 필수 |
| P1 | 회의 복제, 화면 테마 선택, Slack·Teams 전용 형식 변환, 브라우저 종료 중 발송을 위한 별도 서버 대기열 | 후속 릴리스에서 설계·보안 검토 후 구현. MVP 화면에는 미구현 동작을 활성 버튼으로 노출하지 않음 |
| P2 | 조직·권한·공동 편집, 클라우드·기기 간 동기화, 모바일 네이티브 녹음, 회의 봇, 실시간 자막·요약, 통역·다국어 번역, 시스템·탭 오디오 직접 캡처 | 확장 후보이며 구현 확약이 아님. 별도 PRD와 요구사항 ID 부여 후 범위 확정 |

본 개정에서 기존 P0를 하향하지 않는다. 화면별 AC는 P0 요구사항을 구체화하며, 기존 기능 표·비기능 기준을 대체하지 않는다. 범위 충돌 시 1.2의 MVP 포함·제외와 위 우선순위를 함께 적용한다.

모든 저장·생성·전송 작업은 처리 중, 성공, 실패 상태를 구분한다. 실패 시에는 원인과 재시도 방법을 표시하며, 기존에 저장된 정상 데이터를 덮어쓰지 않는다.

### 2.1 음성 녹음 기능

#### 기능 목적

사용자가 회의 음성을 녹음하고, 녹음 중에도 필요한 메모를 남길 수 있도록 한다.

| ID | 요구사항 | 완료·검증 기준 |
|---|---|---|
| REC-01 | 녹음 전 마이크 선택, 입력 상태 확인, 녹음 안내 확인을 제공한다. | 권한 거부·장치 없음·사용 가능 상태를 각각 구분하여 표시한다. |
| REC-02 | 시작, 일시정지, 재개, 종료를 제공한다. | 현재 상태에서 실행 가능한 버튼만 활성화된다. 연속 클릭해도 녹음 인스턴스가 중복 생성되지 않는다. |
| REC-03 | 녹음 시간과 음성 입력 수준을 표시한다. | 시간은 초 단위로 갱신하고, 일시정지 시간은 녹음 길이에 포함하지 않는다. |
| REC-04 | 녹음 데이터를 작은 조각으로 나누어 로컬에 저장한다. | 정상 환경에서 5초 간격으로 데이터 저장을 요청하고, 저장 완료된 마지막 시점을 관리한다. |
| REC-05 | 1회 녹음은 최대 120분으로 제한한다. AI 업로드 파일은 최대 200MiB로 제한한다. | 110분에 경고하고 120분 도달 시 종료한다. 최종 파일이 200MiB를 초과하면 업로드를 차단하고 원본 저장을 안내한다. |
| REC-06 | 녹음 종료 후 원본 재생과 다운로드를 제공한다. | 재생·일시정지·위치 이동이 가능하고, 다운로드 파일을 외부 플레이어에서 재생할 수 있다. |
| REC-07 | 마이크 연결 해제, 저장 실패, 비정상 종료를 처리한다. | 오류 상태와 마지막 저장 시점을 표시하며, 저장된 데이터의 복구 또는 다운로드를 시도할 수 있다. |

구현은 `MediaRecorder`를 사용한다. 녹음 포맷은 브라우저가 지원하는 형식을 확인한 후 선택하고, MVP의 우선 포맷은 `audio/webm;codecs=opus`로 한다. 

**중요한 예외 처리**

브라우저의 녹음 데이터 전달 주기는 정확히 보장되지 않으며, 개별 조각이 각각 재생 가능한 파일인 것도 아니다. 따라서 **“장애가 나도 마지막 5초만 손실된다”는 보장은 하지 않는다.** 복구 시에는 저장된 조각을 순서대로 결합하고 재생 가능 여부를 확인한다. 

녹음 중 새로고침·탭 종료에는 경고를 제공한다. 다만 운영체제 종료나 브라우저 강제 종료까지 막을 수 있다는 전제로 설계하지 않는다.

### 2.2 메모 입력 기능

#### 기능 목적

사용자가 AI에 반영할 맥락, 중요한 발언, 별도 확인 사항을 기록할 수 있도록 한다.

| ID | 요구사항 | 완료·검증 기준 |
|---|---|---|
| NOTE-01 | 회의 전·중·후에 일반 텍스트 메모를 추가·수정·삭제할 수 있다. | 회의당 메모 본문 합계 20,000자를 초과하면 추가 입력을 막고 안내한다. |
| NOTE-02 | 녹음 중 추가한 메모에는 녹음 시점 표시를 붙인다. | `[12:35]`를 선택하면 연결된 음성 위치로 이동한다. 녹음 전·후 메모는 시점 없이 저장한다. |
| NOTE-03 | 메모를 자동 저장한다. | 입력 중단 후 1초 이내 저장을 시작한다. 연속 입력 중에도 최대 5초마다 저장을 시도한다. |
| NOTE-04 | 각 메모의 AI 반영 여부와 중요 표시를 설정한다. | AI 반영을 해제한 메모는 생성 요청에 포함되지 않는다. |
| NOTE-05 | 메모 저장 상태를 표시한다. | ‘저장 중’, ‘저장됨’, ‘저장 실패’를 구분하고 실패 시 재시도할 수 있다. |

**메모와 발언을 구분하는 규칙**

메모는 사용자가 작성한 참고 정보이며, 실제 발언과 동일한 출처로 취급하지 않는다. 예를 들어 전사문에 “납기 미정”이 있고 메모에 “금요일 납품 예정”이 있다면, AI는 금요일 납품을 확정하지 않고 **“납기 확인 필요”**로 표시한다.

자동 저장에 성공한 표시를 확인한 뒤 새로고침했을 때, 본문·중요 표시·AI 반영 여부가 동일하게 복원되어야 한다.

### 2.3 회의 데이터 관리 기능

#### 기본 데이터

| 항목 | 규칙 |
|---|---|
| 회의 ID | 시스템이 생성하는 고유 식별자 |
| 제목 | 1~120자. 미입력 시 `새 회의 YYYY-MM-DD HH:mm` 적용 |
| 회의 일시 | 사용자가 수정 가능. 저장 시 표준 시각과 시간대를 함께 보존 |
| 시간대 | 기본값 `Asia/Seoul` |
| 참석자 | 직접 입력. 화자 이름과 자동으로 동일시하지 않음 |
| 태그 | 회의당 최대 10개, 태그당 최대 20자 |
| 연결 데이터 | 음성, 메모, 전사문, 요약, 상세 회의록, 생성·수정 이력, 웹훅 이력 |

| ID | 요구사항 | 완료·검증 기준 |
|---|---|---|
| DATA-01 | 회의 목록에 제목, 일시, 길이, 처리 상태, 확정 여부를 표시한다. | 기본 정렬은 회의 일시 내림차순이며, 오래된 순으로 변경 가능하다. |
| DATA-02 | 제목·태그·메모·전사문·생성 결과를 검색한다. | 검색 대상 필드를 명시하고, 검색어 제거 시 원래 목록으로 돌아간다. |
| DATA-03 | 기간·처리 상태·확정 여부로 필터링한다. | 복수 필터를 동시에 적용하고 전체 초기화할 수 있다. |
| DATA-04 | 회의 상세에서 원본과 생성 결과를 조회·수정한다. | AI 원본 결과와 사용자가 수정한 내용이 구분된다. |
| DATA-05 | 재생성·확정 시 기존 버전을 보존한다. | 이전 버전 조회 및 복원이 가능하며, 재생성이 기존 수정본을 자동으로 대체하지 않는다. |
| DATA-06 | 회의별 내보내기와 백업 복원을 제공한다. | TXT·Markdown으로 결과를 내보내고, JSON과 음성을 포함한 회의별 ZIP 백업을 복원할 수 있다. |
| DATA-07 | 회의를 영구 삭제할 수 있다. | 확인 후 해당 회의의 로컬 음성·본문·결과·버전이 함께 삭제된다. |

**버전 저장 정책**

자동 저장은 작업 중인 초안을 갱신한다. 반면 AI 생성 완료, 사용자 확정, 이전 버전 복원은 각각 새로운 보존 버전을 만든다. 사용자가 편집한 확정본은 재생성으로 덮어쓰지 않는다.

**백업·복원 정책**

백업에는 형식 버전과 포함 파일 목록을 넣는다. 복원 시 형식·파일 무결성을 먼저 검사하고, 동일한 회의 ID가 있으면 ‘건너뛰기’ 또는 ‘새 회의로 가져오기’를 선택하도록 한다. 가져온 회의는 AI 처리나 웹훅 발송을 자동 실행하지 않는다. API 키와 웹훅 비밀키는 백업에서 제외한다.

**로컬 저장 주의사항**

브라우저 데이터 삭제, 프로필 변경, 서비스 주소 변경 등에 따라 기존 데이터에 접근하지 못할 수 있다. 저장 용량과 자동 정리 정책도 브라우저에 따라 달라진다. 앱은 저장 용량 상태와 백업 필요성을 안내하고, 영구 저장 요청이 거부되더라도 이를 영구 보관 보장으로 표현하지 않는다. 

### 2.4 AI 기반 전사·요약·상세 회의록 생성

#### A. 처리 흐름

녹음 종료 후 아래 순서로 처리한다.

**로컬 음성 저장 완료 → (선택 엔진에 따른) 전송·처리 확인 → STT 전사 → 전사문 로컬 저장 → LLM 요약 생성 → LLM 상세 회의록 생성 → AI 초안 표시**

STT는 설정의 Whisper 또는 AssemblyAI, LLM은 Ollama 또는 OpenAI 중 현재 선택된 엔진을 사용한다. 클라우드 엔진이 포함된 실행에서만 외부 전송 동의를 요구한다. Whisper+Ollama만 사용하는 실행에서는 외부 전송 동의 대신 “로컬 STT·LLM으로 처리합니다” 확인을 거친다.

‘녹음 종료 후 자동 생성’은 기본 활성화하되, **음성 저장 완료 후 AI 처리 선택을 자동으로 안내한다는 의미**로 사용한다. 안내 보조문구는 “음성 저장 후 AI 생성 여부를 확인합니다. 동의 없이 외부로 전송하지 않습니다.”로 한다. 녹음 종료 확인과 AI 처리(또는 외부 전송) 동의는 별도 단계이며, 기본 선택되지 않은 확인 체크와 명시적인 [AI 회의록 생성] 동작을 거쳐야 한다. 설정이 켜져 있거나 과거 회의에서 동의했다는 이유로 이번 회의의 동의를 생략하지 않는다.

[음성만 저장]을 선택하면 음성과 메모를 로컬에 보존하고 SCR-04의 ‘AI 결과 없음’ 상태로 이동한다. 나중에 생성하거나 재생성할 때에도 전송 대상과 실제 입력 범위를 확인한다. 허용한 동일 실행의 상태 조회·재시도에는 동의를 재사용할 수 있으나, 새 실행 또는 전송 입력·범위가 바뀌면 다시 확인한다. 자세한 동작은 4.1 B-1과 6.2를 따른다.

요약과 상세 회의록은 **동일한 입력 버전**을 기준으로 생성한다. 상세 회의록을 짧은 요약만으로 다시 작성하지 않는다.

#### B. 음성의 텍스트 변환 (STT)

STT 엔진은 설정에서 **Whisper(로컬)** 또는 **AssemblyAI(클라우드)** 중 하나를 선택한다. 기본 구현·초기 검증 기준은 AssemblyAI이며, Whisper는 동일 인터페이스로 교체 가능해야 한다.

| ID | 요구사항 | 완료·검증 기준 |
|---|---|---|
| AI-01 | 선택한 STT 엔진으로 녹음 파일을 전사한다. | Whisper·AssemblyAI 모두 업로드(또는 로컬 입력), 전사 요청, 상태 조회, 결과 수신 단계를 공통 인터페이스로 구분한다. |
| AI-02 | 한국어 전사를 기본값으로 사용한다. | 언어 설정은 `ko`이며, 해당 언어를 지원하는 모델로 요청한다. |
| AI-03 | 화자별 발언과 시점을 표시한다. | 화자 정보가 반환되면 ‘화자 A’, ‘화자 B’로 표시하고 사용자가 이름을 수정할 수 있다. 엔진이 화자 구분을 지원하지 않으면 단일 화자로 표시하고 지원 여부를 안내한다. |
| AI-04 | 전사 원문과 수정본을 구분한다. | 원문을 보존하며, 이후 생성에는 사용자가 선택한 최신 수정본을 사용한다. |
| AI-05 | 기존 전사 작업을 재조회할 수 있다. | 저장된 전사 ID(또는 로컬 작업 키)가 있는 경우 새 요청을 만들지 않고 해당 작업의 상태를 조회한다. |

AssemblyAI 초기 한국어 검증 모델은 `speech_models: ["universal-2"]`로 지정한다. AssemblyAI의 지원 언어는 모델별로 다르므로 최신 모델이라는 이유만으로 한국어 지원을 가정하지 않는다. Whisper는 로컬에서 음성을 처리하며 외부 업로드가 없다. Whisper 모델 크기·런타임(예: whisper.cpp, 로컬 Whisper 서버)은 서버 설정으로 분리한다.

화자 구분은 ‘누가 말했는지에 따라 구간을 나누는 기능’이다. 기본 화자 라벨이 실제 사람 이름을 의미하지 않으므로, 참석자 명단만으로 화자 이름을 자동 확정하지 않는다. 

#### C. 생성 결과의 구성

| 결과물 | 필수 구성 | 작성 규칙 |
|---|---|---|
| 핵심 요약 | 회의 목적, 핵심 논의, 주요 결정, 후속 업무 | 핵심 항목 최대 7개, 요약 본문 최대 1,000자. 내용이 적으면 항목을 억지로 채우지 않음 |
| 상세 회의록 | 회의 정보, 안건별 논의, 결정사항, 후속 업무, 미결 사항 | 논의 배경과 결론을 구분하고, 제안·검토·확정을 혼동하지 않음 |
| 후속 업무 | 업무 내용, 담당자, 기한, 근거 | 담당자나 기한이 언급되지 않으면 `null`로 저장하고 화면에는 ‘미정’ 표시 |
| 확인 필요 사항 | 상충 정보, 불명확한 발언, 누락 정보 | AI가 추측해서 확정하지 않고 사용자가 검토할 항목으로 분리 |

각 주요 결정과 후속 업무에는 전사 구간 ID 또는 메모 ID를 연결한다. 사용자가 근거를 선택하면 해당 원문으로 이동해야 한다. 전사 근거는 SCR-04의 근거 오디오 플레이어에서 해당 음성과 원문을 함께 제공한다. 메모 근거는 ‘사용자 메모’로 표시하고, 녹음 시점이 있는 경우에만 오디오 이동을 제공한다. 전사 구간을 임의로 만들어 메모를 실제 발언처럼 표시하지 않는다.

#### D. 품질·실패·재생성 규칙

| ID | 요구사항 | 완료·검증 기준 |
|---|---|---|
| AI-06 | 출력 구조를 고정한다. | 정해진 JSON 구조에 맞지 않거나 필수 필드가 누락된 결과는 정상 완료로 저장하지 않는다. |
| AI-07 | 근거 없는 정보 생성을 억제한다. | 원문에 없는 결정·담당자·기한을 만들어 넣는 평가 사례가 없어야 한다. |
| AI-08 | 요약과 상세 회의록을 개별 재생성한다. | 요약만 실패한 경우 상세 회의록의 정상 결과를 보존한다. |
| AI-09 | 생성 시작 시 입력과 프롬프트를 고정한다. | 생성 중 메모가 변경되어도 해당 실행의 입력 버전은 바뀌지 않는다. |
| AI-10 | 입력 변경 시 결과의 최신 여부를 표시한다. | 전사문·메모 수정 후 기존 결과에 ‘원문 변경됨 — 재생성 필요’를 표시한다. |
| AI-11 | 긴 회의를 처리한다. | 입력 한도를 초과하면 발언 구간 단위로 분할 처리하며, 뒤쪽 내용을 조용히 잘라내지 않는다. |
| AI-12 | 빈 전사·무음·거절·응답 중단을 구분한다. | 빈 결과를 성공한 회의록처럼 표시하지 않고 원인과 다음 행동을 제공한다. |

GPT/Ollama 출력은 Structured Outputs(또는 동등한 JSON 스키마 강제)를 사용해 필드 구조를 고정한다. 다만 **형식이 올바른 것과 내용이 사실인 것은 별개**이므로, 근거 확인과 사용자 검토 절차는 유지한다. 

긴 입력은 초기 기준으로 32,000토큰을 넘으면 분할한다. 토큰은 AI가 입력과 출력을 처리하는 텍스트 단위다. 분할 결과에는 원래 발언 ID를 보존하고, 합치는 단계에서 중복을 제거한다. 실제 분할 기준과 출력 예산은 채택 모델의 한도 안에서 설정한다.

### 2.5 설정 관리: AI 엔진 · 프롬프트

프롬프트는 AI에게 결과의 구성과 작성 방식을 지시하는 문장이다. STT·LLM 엔진은 설정에서 선택하며, 선택값은 생성 결과에 기록한다.

| ID | 요구사항 | 완료·검증 기준 |
|---|---|---|
| SET-01 | 요약용과 상세 회의록용 프롬프트를 별도로 편집한다. | 한쪽 변경이 다른 쪽에 영향을 주지 않는다. |
| SET-02 | 각 사용자 프롬프트는 20~4,000자로 제한한다. | 글자 수를 표시하고 범위를 벗어나면 저장을 차단한다. |
| SET-03 | 기본값 복원을 제공한다. | 확인 후 선택한 프롬프트만 기본값으로 되돌린다. |
| SET-04 | 프롬프트 변경 이력을 관리한다. | 저장 시 버전을 증가시키고, 생성 결과에 사용한 버전을 기록한다. |
| SET-05 | 샘플 입력으로 시험 생성할 수 있다. | 선택한 LLM이 클라우드인 경우 실제 외부 API 호출·비용 가능성을 실행 전에 표시한다. Ollama인 경우 로컬 호출임을 표시한다. |
| SET-06 | 일반 설정을 제공한다. | 시간대, 자동 생성, 기본 화면 테마, 외부 전송 설정이 재실행 후 유지된다. |
| SET-07 | STT 엔진을 선택한다. | Whisper 또는 AssemblyAI 중 하나를 저장·복원하며, 생성 실행에 사용한 엔진을 기록한다. |
| SET-08 | LLM 엔진을 선택한다. | Ollama 또는 OpenAI 중 하나를 저장·복원하며, 생성 실행에 사용한 엔진·모델 ID를 기록한다. |

**AI 엔진 선택 구조**

```text
MeetingAI
├── STT
│   ├── Whisper      (로컬)
│   └── AssemblyAI   (클라우드)
└── LLM
    ├── Ollama       (로컬)
    └── OpenAI       (클라우드)
```

엔진 조합은 자유롭게 선택할 수 있다. 예: Whisper+Ollama(완전 로컬), AssemblyAI+OpenAI(완전 클라우드), Whisper+OpenAI 또는 AssemblyAI+Ollama(혼합). 미연결·미설치 엔진은 선택 저장을 막거나 연결 실패 상태를 표시한다.

**프롬프트 적용 구조**

`앱의 고정 규칙 + 사용자의 작성 지침 + 회의 정보·전사문·선택 메모 + 출력 형식`

원문과 메모는 앱이 자동 첨부한다. 사용자는 문체와 강조 항목을 수정할 수 있지만, 출처 보존·정보 추측 금지·출력 구조 등의 고정 규칙은 제거할 수 없다.

**기본 요약용 사용자 프롬프트**

```text
이 회의의 핵심 내용을 한국어 업무 보고 문체로 요약하세요.
회의 목적, 주요 논의, 결정사항, 후속 업무를 구분하세요.

주요 결정과 후속 업무에는 근거를 연결하세요.
```

**기본 상세 회의록용 사용자 프롬프트**

```text
회의 내용을 안건별 상세 회의록으로 작성하세요.
각 안건은 논의 배경, 주요 의견, 결론, 미결 사항으로 구분하세요.

발언과 메모가 충돌하면 확인 필요 사항으로 표시하세요.
원문에 없는 사실이나 발언을 추가하지 마세요.
```

**API 키 · 로컬 엔진 관리**

AssemblyAI·OpenAI API 키와 Ollama·Whisper 연결 설정은 서버 실행 환경에만 둔다. 설정 화면에는 ‘설정됨’, ‘연결 실패’, ‘로컬 사용 가능’과 같은 상태만 표시하고, 실제 키를 브라우저에 전달하지 않는다. Next.js에서 `NEXT_PUBLIC_`로 시작하는 환경변수는 브라우저 코드에 포함될 수 있으므로 비밀키에 해당 접두사를 사용하지 않는다. 

### 2.6 데이터 외부 연동: 웹훅

웹훅은 특정 사건이 발생했을 때 다른 시스템의 지정된 주소로 데이터를 보내는 방식이다.

#### 기본 정책

**기본값은 외부 연동 꺼짐이며, 활성화한 경우에도 사용자가 확정한 버전만 자동 전송한다.** 여기서 자동 전송은 확정 시 대상·항목을 확인하고 [확정 및 전송]을 선택한 뒤 대기열에서 발송한다는 뜻이다. 설정 활성화만으로 과거 확정본을 일괄 발송하지 않으며, [확정만]은 전송하지 않는다.

MVP는 범용 JSON 수신처 1개를 지원한다. 수신 URL과 서명 비밀키는 설치자가 서버 환경설정에 등록하고, 사용자 화면에서는 연결 선택·활성화·전송 항목 선택·시험 발송을 제공한다.

| ID | 요구사항 | 완료·검증 기준 |
|---|---|---|
| WH-01 | 확정된 회의록을 HTTP POST로 전송한다. | 전송 데이터는 해당 확정 버전의 내용과 일치한다. |
| WH-02 | 전송 항목을 선택한다. | 기본 포함은 회의 정보·요약·상세 회의록·후속 업무. 전사문·메모는 기본 제외, 음성은 MVP 전송 제외 |
| WH-03 | 실제 회의 데이터 없는 시험 발송을 제공한다. | 응답 상태와 성공·실패 이유를 표시한다. |
| WH-04 | 발송 상태와 시도 이력을 저장한다. | 이벤트 ID, 대상 별칭, 발송 시각, 시도 횟수, 응답 코드가 조회된다. |
| WH-05 | 일시적 실패를 재시도한다. | 최초 발송 포함 최대 4회. 실패 후 각각 1분·5분·30분 간격으로 재시도 |
| WH-06 | 중복 처리 방지 정보를 제공한다. | 같은 전송의 재시도에는 같은 `event_id`를 사용한다. 새로운 확정 버전은 새 ID를 사용한다. |
| WH-07 | 발송 전 확인과 대기 취소를 제공한다. | 사용자는 대상·포함 항목을 확인하고 아직 보내지 않은 이벤트를 취소할 수 있다. |

아래는 전송 형식을 설명하기 위한 예시다.

```json
{
  "schema_version": "1.0",
  "event_id": "evt_0001",
  "event_type": "meeting.approved",
  "occurred_at": "2026-09-10T07:00:00Z",
  "meeting": {
    "id": "meeting_0001",
    "title": "주간 프로젝트 회의",
    "timezone": "Asia/Seoul",
    "approved_version": 2
  },
  "content": {
    "summary": "시제품 검토 일정과 추가 확인 항목을 논의했다.",
    "action_items": [
      {
        "task": "시제품 시험 결과 정리",
        "owner": null,
        "due_date": null,
        "source_refs": ["utterance_012"]
      }
    ]
  }
}
```

선택한 전송 항목에 따라 상세 회의록 등 추가 필드가 포함된다. 이 형식을 모든 외부 서비스가 그대로 수용한다고 가정하지 않는다. Slack·Teams 등의 전용 형식 변환은 P1으로 분리한다.

#### 발송 규칙

응답 제한 시간은 10초로 한다. HTTP 2xx는 성공, 네트워크 오류·408·429·5xx는 재시도 대상으로 한다. 유효한 `Retry-After`가 있으면 이를 우선 적용한다. 다른 4xx는 설정 수정 전까지 자동 재시도하지 않고, 리다이렉트는 따라가지 않는다.

서버가 요청을 처리했지만 응답이 유실되면 중복 수신이 발생할 수 있다. 따라서 **정확히 한 번만 도착한다는 보장은 하지 않으며**, 수신 시스템은 `event_id`로 중복을 제거해야 한다.

로컬 발송 대기열은 브라우저 종료 시 중단되고 다음 실행 때 재개된다. 브라우저가 닫혀 있어도 정시에 발송하는 기능은 별도 서버 작업 대기열이 필요한 후속 범위다.

수신 주소는 서버의 허용 목록으로 제한한다. 내부망·루프백·클라우드 메타데이터 주소 차단, DNS 검증, 리다이렉트 차단 등을 적용하여 SSRF를 방지한다. SSRF는 서버를 이용해 의도하지 않은 주소에 요청을 보내게 하는 공격이다.

## 3. 사용자 흐름·상태·데이터 구조

### 3.1 주요 사용자 흐름

| 단계 | 사용자 행동 | 시스템 처리 |
|---|---|---|
| 1. 회의 준비 | 새 회의 생성, 제목·참석자 입력 | 회의 기본 정보를 로컬에 저장 |
| 2. 녹음 준비 | 마이크 확인, 녹음 안내 확인 | 장치·권한·저장 가능 상태 점검 |
| 3. 회의 진행 | 녹음, 필요 시 메모·일시정지 | 음성과 메모를 각각 자동 저장 |
| 4. 회의 종료 | 녹음 종료 확인 후 AI 생성 또는 음성만 저장 선택 | 로컬 저장 성공 후 별도의 외부 전송 동의 UX 표시. 동의 없는 외부 요청 금지 |
| 5. 자동 생성 | 진행 상태 확인 | 전사 → 요약 → 상세 회의록 생성 |
| 6. 검토 | 근거 확인, 문구·담당자·기한 수정 | 수정본 저장, 변경 상태 표시 |
| 7. 확정 | 회의록 확정 및 활성 연동의 대상·포함 항목 확인 | 확정 버전 생성. 외부 전송 확인을 완료한 경우에만 해당 버전을 대기열에 등록 |
| 8. 재활용 | 검색·내보내기·백업 | 로컬 데이터에서 조회·출력 |

화면 흐름은 **SCR-01 목록 → SCR-02 새 회의 생성·녹음 → 음성 저장 → AI 처리 선택 → SCR-03 처리 → SCR-04 검토·확정 → SCR-06 전송 확인·이력**이다. ‘음성만 저장’은 SCR-03을 거치지 않고 SCR-04로 이동한다. SCR-05는 모든 주요 화면의 헤더에서 접근하며, SCR-06은 SCR-04의 외부 연동 탭으로 제공한다. 준비 상태 회의를 다시 열면 SCR-02, 진행 중 AI 작업을 열면 SCR-03, 나머지는 SCR-04로 연결한다.

### 3.2 상태 관리

녹음, AI 처리, 사용자 검토, 웹훅 상태는 서로 분리한다. 예를 들어 웹훅 실패 때문에 정상 생성된 회의록까지 ‘생성 실패’로 바뀌어서는 안 된다.

| 대상 | 상태 |
|---|---|
| 녹음 | 대기 → 녹음 중 ↔ 일시정지 → 저장 중 → 저장 완료 / 복구 필요 |
| 전사 | 대기 → 업로드 중 → 처리 중 → 완료 / 실패 / 상태 확인 필요 |
| 요약·상세 생성 | 대기 → 생성 중 → 완료 / 실패 / 입력 변경됨 |
| 검토 | AI 초안 → 수정 중 → 확정 |
| 웹훅 | 미설정 / 대기 → 전송 중 → 성공 / 재시도 대기 / 실패 / 취소 |

#### 상위 회의 상태(Meeting Display Status)

목록과 헤더에는 아래 파생 상태를 사용한다. 원본의 녹음·전사·요약·상세·검토·웹훅 상태를 하나의 값으로 덮어쓰지 않는다. 상위 상태는 현재 작업·현재 표시 버전에서 계산하며, 과거에 해결된 오류와 이전 확정 버전의 발송 이력은 현재 배지를 바꾸지 않는다.

| 내부 조건 | 사용자 표시 | 다음 행동·보조 정보 |
|---|---|---|
| 회의 생성 후 녹음 전 | 준비 | 녹음 준비 |
| 녹음 진행 또는 일시정지 | 녹음 중 / 일시정지 | 재개·종료, 마지막 음성 저장 시점 |
| 종료 후 음성 파일 저장 미완료 | 저장 중 | 저장 완료 대기. AI 전송 불가 |
| 음성 저장 완료, AI 미실행 | 음성 저장됨 | 원본 재생·메모·AI 생성 |
| 업로드·전사·요약·상세 실행 중 | AI 처리 중 | 실제 처리 단계·경과 시간 |
| 결과 생성 또는 수정·복원으로 새 초안 존재 | 검토 필요 | 근거 확인·수정·확정. 입력 변경 경고 병기 |
| 현재 버전 확정, 전송 성공 조건 미충족 | 확정됨 | 전송 대기·전송 중·연동 꺼짐 등을 보조 표시 |
| 현재 확정 버전에 대한 전송 성공 | 전송 완료 | 해당 버전·수신처·발송 시각 |
| 현재 AI 작업 실패 | 처리 실패 | 실패 단계 재시도, 정상 부분 결과 확인 |
| 현재 확정 버전 웹훅 실패 | 전송 실패 | 재시도 여부·다음 시각, 확정본 유지 |
| 음성 저장 실패·중단으로 복구 판단 필요 | 복구 필요 | 마지막 저장 시점·복구·다운로드 |
| 외부 요청 성공 여부 불명확 | 상태 확인 필요 | 기존 작업 조회 또는 비용 안내 후 재실행 판단 |

동시 조건의 우선 표시는 **복구 필요 → 녹음 중/일시정지 → 저장 중 → 현재 실행 중인 AI 처리 → 상태 확인 필요 → 처리 실패 → 전송 실패 → 검토 필요 → 전송 완료 → 확정됨 → 음성 저장됨 → 준비**로 한다. 실시간 녹음·저장과 현재 재시도 중인 작업을 과거 실패가 가리지 않게 한다. ‘전송 완료’는 ‘현재 확정 버전 전송 성공’으로 제한하고 ‘확정됨’보다 먼저 평가한다. 이는 상세 UI/UX 초안의 우선순위에서 누락된 저장·일시정지·AI 미실행 상태와 확정/전송 성공의 중첩을 정합화한 규칙이다.

새 초안을 수정하더라도 과거 확정본·전송 성공 이력은 보존한다. 목록의 확정 필터는 현재 표시 버전 기준으로 적용하고, 과거 확정본 존재 여부는 이력에서 따로 확인한다. 요약 성공·상세 실패처럼 부분 완료된 경우 ‘처리 실패 · 요약 저장됨’을 함께 표시한다.

**중단 후 재개 규칙**

전사 ID가 이미 저장된 작업은 같은 ID로 상태 조회를 재개한다. 반대로 요청은 전송했지만 응답을 받지 못해 ID가 없는 경우에는 성공 여부를 단정하지 않는다.

GPT 응답을 로컬에 저장하기 전에 탭이 닫힌 경우에도 결과 복구를 보장하지 않는다. 재실행 시 ‘결과 미저장 가능’ 상태를 표시하고, 재생성에 추가 비용이 발생할 수 있음을 안내한다.

### 3.3 로컬 데이터 구조

| 저장 단위 | 주요 필드 | 용도 |
|---|---|---|

| `transcripts` | 전사 ID, 원문, 수정본, 화자, 시작·종료 시점, 버전 | 발언 및 근거 |
| `generations` | 종류, 결과, 입력 버전, 프롬프트 사본·버전, 모델 ID, 생성 시각 | 요약·상세 회의록 이력 |

| `cleanupJobs` | 외부 전사 ID, 삭제 요청 상태, 재시도 시각 | 외부 데이터 삭제 요청 추적 |
| `aiConsents` | 동의 ID, 회의 ID, 실행 ID, 입력 버전·해시, 전송 항목, 제공업체, 안내 버전, 동의 시각 | 해당 AI 실행의 외부 전송 허용 기록 |

기존 저장 단위에는 다음 필드를 추가한다. `jobs`는 동의 ID·입력 해시·단계별 상태·시작 시각을 참조한다. `generations`의 근거 참조에는 출처 종류, 원문 버전, 구간/메모 ID, 녹음 세션 ID, 시작·종료 시점을 보존한다. `webhookDeliveries`에는 대상 별칭, 사용자 전송 확인 시각, 선택 항목과 확정 버전의 불변 스냅샷을 저장한다. 상위 회의 상태는 이들 원본에서 계산하며, 캐시할 경우 원본 변경과 함께 갱신한다.

백업으로 복원한 회의의 동의 기록은 과거 이력일 뿐 새 외부 실행 허용으로 사용하지 않는다. 새 필드가 없는 v0.1.1 데이터는 ‘동의 없음’으로 이관하고 외부 처리를 자동 실행하지 않는다. 데이터 형식 버전은 PRD v0.2와 별도로 올리며, 이전 형식 복원·마이그레이션을 QA에 포함한다.

시간은 표준 형식으로 저장하고 표시할 때 시간대를 적용한다. 버전 참조에는 번호뿐 아니라 입력 해시를 함께 저장해, 어떤 원문으로 결과를 만들었는지 비교할 수 있도록 한다. 해시는 데이터가 동일한지 비교하기 위한 식별값이다.

#### B. SCR-02~04 회의 진행·상세 화면

##### B-1. SCR-02 새 회의 생성·녹음·AI 처리 선택

새 회의는 녹음 전에 아래 화면(`/meetings/new`)에서 생성한다. **이 화면을 열기만 해서는 IndexedDB에 회의를 만들지 않는다.** `[취소]` 또는 `← 회의 목록`으로 나가면 SCR-01 목록에 항목이 추가되지 않는다.

‘회의 시작’은 회의 기본 정보를 로컬에 저장하고 `/meetings/{meetingId}/record` 마이크·녹음 화면을 여는 동작이며 자동 녹음을 시작하지 않는다.

```text
← 회의 목록
새 회의

회의 제목  [                              ] 0 / 120
회의 일시  [2026.09.10] [14:00]  Asia/Seoul
참석자     [                              ] 선택
태그       [+ 태그 추가]                     선택

[취소]                              [회의 시작]
```

제목은 공백만 입력해도 미입력으로 보고 `새 회의 YYYY-MM-DD HH:mm`을 적용한다. 제목 120자 초과, 유효하지 않은 일시, 태그 10개/각 20자 초과는 해당 필드에서 안내하고 저장을 막는다. 일시 기본값은 현재 시각이며 시간대는 브라우저(또는 설정값)를 사용한다. 참석자는 자유 입력이며 AI 화자 라벨과 자동 연결하지 않는다. 저장 실패 시 입력값을 유지하고 재시도한다. 중복 클릭해도 회의는 1건만 생성한다.

회의 생성 후 마이크 선택·입력 수준·녹음 안내를 표시한다. 마이크 권한 요청은 사용자 녹음 준비 행동과 연결하고, [녹음 시작]은 권한·장치·저장 가능 조건을 만족할 때만 실행한다. 녹음 제어와 메모는 같은 작업 영역에 둔다. 일시정지 중에는 [재개]와 [종료]를 제공한다.

녹음 중 메모 시점은 일시정지 시간을 제외한 오디오 타임라인을 사용한다. MVP에서 녹음 중 타임스탬프는 기록하되 재생은 녹음 종료·저장 완료 후 제공하여 재생음이 녹음에 재유입되지 않게 한다. 시점 없는 메모는 오디오 이동을 제공하지 않는다.

녹음 종료 확인에서는 현재 녹음 길이와 “녹음을 종료하면 음성 파일을 저장합니다.”를 표시한다. 마지막 음성 저장 성공 전에는 아래 AI 처리 선택을 활성화하지 않는다.

```text
AI 회의록을 생성하시겠습니까?

현재 엔진: STT AssemblyAI · LLM OpenAI

AI 처리 과정에서 다음 데이터가 외부 AI 서비스로 전송됩니다.
AssemblyAI: 회의 음성
OpenAI: 전사문, ‘AI 반영’으로 선택한 메모, 생성에 사용하는 회의 정보·프롬프트
제공업체 데이터 처리 안내 [보기]

☐ 위 내용을 확인하고 이번 AI 처리를 위한 외부 전송에 동의합니다.

[음성만 저장]                         [AI 회의록 생성]
```

Whisper+Ollama처럼 외부 전송이 없는 조합에서는 전송 목록 대신 “음성·전사문·메모는 이 기기(로컬 엔진)에서만 처리됩니다.”를 표시하고, 동일하게 확인 체크와 [AI 회의록 생성]을 거친다. 혼합 조합에서는 실제로 외부로 나가는 항목만 나열한다.

체크는 기본 해제이며 미선택 시 생성 버튼은 비활성화한다. 체크만으로 전송·처리를 시작하지 않고 생성 버튼 선택 시 동의와 입력 스냅샷·선택 엔진을 저장한 뒤 요청한다. 닫기·취소·음성만 저장은 외부 요청 없이 로컬 데이터를 유지한다. 재생성 시에는 이미 저장된 전사를 사용하는지 음성을 다시 전사하는지에 따라 실제 전송 대상만 안내한다. 선택하지 않은 메모는 요청 본문에 포함하지 않는다. 생성 실행이 시작된 뒤 바뀐 메모는 그 실행에 추가하지 않는다.

##### B-2. SCR-03 AI 처리

단계는 `SAVE_AUDIO → UPLOAD_AUDIO → TRANSCRIBE → GENERATE_SUMMARY → GENERATE_MINUTES → COMPLETE`로 구분한다. Whisper(로컬 STT)에서는 `UPLOAD_AUDIO`를 ‘로컬 입력 준비’로 표시하며 클라우드 업로드를 실행하지 않는다. SCR-03 진입 시 음성 저장은 완료 상태여야 한다. 기존 전사를 재사용하는 실행에서는 업로드·전사를 ‘기존 전사 사용’으로 표시하며 실행하지 않은 단계를 실행 완료처럼 표현하지 않는다.

단계별 대기·처리 중·성공·실패와 경과 시간, **사용 중인 STT·LLM 엔진**을 표시한다. 업로드 바이트 수를 실제 측정할 수 있을 때만 퍼센트를 제공하며 전사·LLM 생성에는 임의 퍼센트를 쓰지 않는다. 실패 단계 재시도와 [현재 결과 확인]을 제공한다. 예를 들어 요약 성공·상세 실패에서는 요약을 유지한 채 상세만 재시도한다.

네트워크 단절 시 “인터넷 연결이 끊어졌습니다. 녹음 파일은 이 브라우저에 저장되어 있습니다.”와 [다시 시도]·[회의로 돌아가기]를 표시한다. 이 문구는 실제 음성 저장 성공을 확인한 경우에만 사용한다. 비용 요청의 응답 유실은 3.2의 상태 확인 규칙을 따른다.

완료 시 [회의록 검토하기]를 제공한다. 사용자가 해당 처리 화면을 보고 있는 경우에만 1~2초 후 SCR-04로 이동한다. 다른 화면에서 작업 중이면 이동시키지 않고 완료 알림과 링크를 제공한다.

##### B-3. SCR-04 회의 결과·검토

아래 결과 탭은 요약·상세 회의록·전사문·이력·외부 연동으로 구성한다. 음성만 저장한 회의에는 ‘AI 결과 없음’, 원본 플레이어, 메모와 [AI 회의록 생성]을 제공하며 빈 AI 결과를 검토 완료·확정 상태로 취급하지 않는다. 부분 생성은 정상 결과와 미완료 항목을 각각 표시한다.

결정사항·후속 업무에서 근거를 선택하면 같은 화면의 패널에 연결된 원문과 오디오를 표시한다.

```text
근거 발언                          [닫기]
▶ 12:35 ━━━━━●━━━━━━━━━━ 13:02  [계속 재생]
화자 B
“시험 결과를 다음 회의 전에 정리해서…”
[전사문에서 보기]
```

플레이어는 재생·일시정지·위치 이동·현재/전체 시간·음량을 제공한다. 근거 선택 시 `source.startTime`으로 이동하고 발언을 강조한다. 명시적 재생 동작으로 재생을 시작하며 자동 재생 제한으로 실패해도 재생 버튼을 유지한다. 구간 재생은 `min(source.endTime + 3초, 전체 음성 길이)`에서 멈추고 [계속 재생]으로 이어 들을 수 있다. 종료 시점이 없으면 제한을 추정하지 않고 수동 정지 가능한 일반 재생을 제공한다.

전사 근거는 화자·원문 버전·발언 내용을 함께 표시하고 [전사문에서 보기]로 해당 구간에 이동한다. 메모 근거는 본문·중요 표시·AI 반영 여부를 보여준다. 오디오 누락·손상·범위 밖 시점은 오류를 안내하고 확인 가능한 원문을 유지하며, 재생 성공처럼 표시하지 않는다. 잘못된 근거 ID는 링크를 비활성화하고 ‘근거 확인 필요’를 표시한다.

전사문에서 화자명·본문을 수정하면 원문을 보존한 수정본과 입력 버전을 갱신한다. AI 반영 메모·전사 수정 후에는 ‘원문 변경됨 — 재생성 필요’를 표시한다. AI 반영 해제된 메모의 본문만 수정한 경우처럼 생성 입력이 같으면 불필요한 경고를 만들지 않는다. 중요 표시·반영 선택 변경은 실제 입력 스냅샷 변화에 따라 판단한다.

AI 결과 편집은 작업 초안을 자동 저장하며 AI 원본을 보존한다. 확정 확인에는 남은 확인 필요 항목 수를 표시한다. 미해결 항목이 있어도 경고 확인 후 확정할 수 있으나 확인 필요 문구를 자동 삭제하거나 사실로 바꾸지 않는다. 확정 시 불변 보존 버전을 생성한다. 확정 이후 수정은 새 작업 초안으로 시작하고 재확정 전에는 기존 전송본을 변경하지 않는다. 이전 버전 복원도 새 보존 버전과 검토할 초안을 만들며 자동 확정·외부 발송하지 않는다.

웹훅이 활성화되어 있으면 확정 대화상자에 대상·포함 항목을 표시하고 [확정 및 전송]과 [확정만]을 구분한다. [확정 및 전송]을 선택한 경우에만 그 버전의 발송 대기열을 만든다. 상세한 전송 확인·이력은 SCR-06을 따른다.

#### C. SCR-05 설정 팝업

설정은 일반, AI 엔진, AI 프롬프트, 외부 연동, 저장·백업, 데이터 처리 안내로 구분한다.

PC에서는 최대 너비 720px, 높이 80vh의 대화상자를 사용한다. 저장하지 않은 프롬프트·엔진 변경이 있는 상태에서 닫으면 변경사항 폐기 여부를 확인한다.

```text
설정                                         [닫기]

[ 일반 ] [ AI 엔진 ] [ AI 프롬프트 ] [ 외부 연동 ] [ 저장·백업 ] [ 안내 ]

┌──────────────────────────────────────┐
│ AI 엔진                               │
│                                      │
│ STT (음성→텍스트)                     │
│ ( ) Whisper        로컬              │
│ (•) AssemblyAI     클라우드          │
│                                      │
│ LLM (요약·상세 회의록)                │
│ ( ) Ollama         로컬              │
│ (•) OpenAI         클라우드          │
│                                      │
│ AssemblyAI ● 설정됨 · 연결 확인 성공  │
│ OpenAI     ● 설정됨 · 연결 확인 성공  │
│ Whisper    ● 로컬 사용 가능           │
│ Ollama     ! 연결 실패               │
│                                      │
│                         [저장]        │
└──────────────────────────────────────┘
```

일반 설정은 시간대와 녹음 종료 후 AI 생성 안내 여부를 제공한다. SET-06의 기본 화면 테마 적용·저장·복원은 P0로 유지하고, 사용자가 여러 테마를 선택하는 확장 UI는 P1이다. 요약용·상세용 프롬프트는 각각 20~4,000자이며 글자 수와 필드 오류를 표시한다. 저장·기본값 복원은 선택한 프롬프트에만 적용하고, 저장하지 않은 변경을 닫을 때 폐기 여부를 확인한다.

[샘플로 시험 생성]은 실제 회의 대신 고정된 샘플을 사용한다. 선택한 LLM이 OpenAI이면 “실제 OpenAI API를 호출하며 비용이 발생할 수 있습니다. 실제 회의 데이터는 사용하지 않습니다.”를, Ollama이면 “로컬 Ollama를 호출합니다. 실제 회의 데이터는 사용하지 않습니다.”를 표시하고 [시험 생성]으로 시작한다. API 키는 표시하지 않고 엔진 선택·연결 상태만 제공한다. 저장·백업 탭은 용량 추정값과 회의별 ZIP 백업·복원 경로를 제공하며 전체 자동 백업을 암시하지 않는다.

#### D. SCR-06 외부 연동·전송 이력

SCR-04의 외부 연동 탭에서는 현재 회의의 확정 버전·발송 상태·이력을 표시하고 SCR-05의 외부 연동 설정으로 연결한다. 공통 설정은 수신처 1개의 별칭 선택, 기본 꺼짐, 전송 포함 항목, 샘플 시험 발송을 제공한다. 음성 전송 옵션은 제공하지 않는다.

```text
외부 연동                                    [설정]
현재 확정 버전 v3 · 수신처 사내 업무관리 시스템
포함: 회의 정보 / 요약 / 상세 회의록 / 후속 업무
제외: 전사문 / 메모     음성 전송은 지원하지 않습니다.

[확정본 전송]

전송 이력
버전 v3 · 대기 · 다음 시도 시각          [대기 취소]
버전 v2 · 성공 · 전송 시각 · HTTP 200     [상세]
버전 v1 · 실패 · 4회 시도                [상세]
```

확정본이 없으면 [확정본 전송]을 비활성화하고 검토·확정을 안내한다. 발송 전 확인에는 대상 별칭, 확정 버전, 포함·제외 항목, 실제 전송 내용 미리보기를 제공한다. 미리보기와 실제 요청은 같은 불변 스냅샷을 사용한다. AI 외부 전송 동의는 웹훅 동의를 대신하지 않는다. SCR-04에서 [확정 및 전송]으로 동일 내용을 확인한 경우 중복 대화상자는 띄우지 않는다.

시험 발송은 대상과 ‘실제 회의 내용 미포함’을 확인한 뒤 고정 샘플을 보낸다. 결과에는 HTTP 상태, 성공·실패 이유, 응답 시간을 표시하되 키·민감한 응답 본문은 노출하지 않는다.

이력 상세에는 이벤트 ID, 확정 버전, 대상, 선택 항목, 시도별 시각·응답 코드, 다음 재시도 시각을 제공한다. 재시도 가능한 실패는 2.6의 최대 4회·간격을 따르고, 같은 전송의 수동 재시도에도 같은 이벤트 ID를 사용한다. 발송 중 중복 클릭을 막는다. 명시적인 새 발송은 재시도와 구분해 확인하며 새로운 이벤트를 생성한다.

아직 보내지 않은 대기 또는 예약 재시도는 취소할 수 있다. 이미 전송 중인 요청과 성공한 수신을 취소·회수했다고 표시하지 않는다. 설정 변경은 기존 대기 스냅샷을 바꾸지 않으며, 사용자가 대기를 취소하고 변경된 설정으로 새 발송을 확인하도록 한다. 앱 종료 중에는 발송되지 않고 다음 실행에 대기 상태를 복원한다.

### 4.3 디자인 시스템

디자인 토큰은 색상·간격·글자 크기처럼 여러 화면에서 공통으로 사용하는 값이다. 이를 Tailwind의 공통 테마 변수로 관리한다. 

| 항목 | 기준 |
|---|---|
| 기본 배경 | `#F8FAFC` |
| 본문 색상 | `#0F172A` |
| 주요 동작 | `#2563EB` |
| 위험·녹음 상태 | `#B91C1C` 계열과 명시적인 상태 문구 |
| 글자 크기 | 본문 16px, 보조 14px, 화면 제목 24px |
| 본문 줄 높이 | 1.5 이상 |
| 간격 | 4·8·12·16·24·32px |
| 모서리 | 기본 8px |
| 주요 조작 영역 | 최소 높이 44px |
| 상태 표현 | 색상만 사용하지 않고 아이콘·텍스트 병행 |

접근성 검수에는 일반 본문 대비 4.5:1 이상, 키보드 조작, 포커스 표시, 대화상자의 초점 관리, 입력 오류 안내를 포함한다. 접근성 검토 기준은 WCAG 2.2 AA를 사용하며, 일부 항목 구현만으로 전체 준수를 선언하지 않는다. 

### 4.4 반응형·안내 문구

화면 너비 1,280px 이상은 나란한 편집 영역, 768~1,279px은 접이식 목록과 단일 작업 영역, 767px 이하는 세로 배치를 사용한다. 360px 너비에서 가로 넘침이 없어야 하며, 모바일 녹음은 지원 범위가 아님을 명시한다.

핵심 안내 문구는 다음과 같이 통일한다.

> “회의 데이터는 이 브라우저에 저장됩니다. 중요한 회의는 백업해 주세요.”

> “AI 처리는 설정한 STT·LLM 엔진을 사용합니다. 클라우드 엔진을 선택한 경우에만 해당 데이터가 외부로 전송됩니다.”

> “AI가 작성한 초안입니다. 결정사항·담당자·기한을 확인한 후 확정해 주세요.”

## 5. 기술 스택 및 구현 구조

### 5.1 기술 스택

| 영역 | 선택 기술 | 담당 역할 |
|---|---|---|
| 웹 프레임워크 | Next.js App Router + TypeScript | 화면, 라우팅, 서버 API |
| 스타일 | Tailwind CSS | 디자인 토큰과 반응형 UI |
| 녹음 | `getUserMedia` + `MediaRecorder` | 마이크 접근과 음성 수집 |
| STT (선택) | Whisper(로컬) · AssemblyAI(클라우드) | 한국어 전사, 화자·시점 정보 |
| LLM (선택) | Ollama(로컬) · OpenAI GPT(클라우드) | 구조화된 요약·상세 회의록 생성 |
| 로컬 데이터 | IndexedDB + Dexie | 회의·음성·버전·대기열 저장 |
| 서버 실행 | Node.js 런타임 | 비밀키 관리, 엔진 중계, 웹훅 서명 |
| 데이터 검증 | TypeScript + Zod | 입력·출력 형식 검사 |
| 테스트 | Vitest + Playwright | 단위 테스트와 브라우저 전체 흐름 테스트 |

**AI 엔진 아키텍처**

```text
MeetingAI
├── STT
│   ├── Whisper
│   └── AssemblyAI
└── LLM
    ├── Ollama
    └── OpenAI
```

STT·LLM은 공통 어댑터 인터페이스로 추상화한다. 설정에서 선택한 엔진만 실행에 사용하며, 생성 결과에는 `sttProvider`·`llmProvider`·모델 ID를 기록한다. Dexie는 IndexedDB를 다루기 위한 도구로 사용하며, Dexie Cloud 동기화는 사용하지 않는다. Next.js의 공식 테스트 가이드를 기준으로 단위 테스트와 브라우저 기반 E2E 테스트를 구성한다. E2E는 실제 사용자 동작을 처음부터 끝까지 검증하는 테스트다.

OpenAI 모델은 `OPENAI_MODEL`을 서버 설정으로 분리한다. 초기 검증 기준은 Responses API와 Structured Outputs를 지원하는 `gpt-4.1-mini-2025-04-14`로 고정하고, 다른 GPT 모델을 채택할 때에는 동일한 품질 평가를 다시 통과하도록 한다. Ollama 모델은 `OLLAMA_MODEL`로 분리하며, Structured Outputs(또는 동등한 JSON 스키마 강제)가 가능한 모델을 초기 검증 기준으로 둔다. Whisper 모델·런타임은 `WHISPER_*` 서버 설정으로 분리한다. 이는 최신 모델이라는 의미가 아니라 **재현 가능한 초기 평가 기준**이다. 

### 5.2 클라이언트와 서버 역할 분리

| 클라이언트: 브라우저 | 서버: Next.js |
|---|---|
| 녹음·메모·회의 편집 | 외부 API 인증 · 로컬 엔진 연결 |
| IndexedDB 저장·조회 | 음성 업로드·로컬 STT 중계 |
| 작업 ID와 진행 상태 보관 | 전사 요청·조회·삭제 중계 |
| 생성 결과·버전 보관 | LLM 요청과 결과 검증 |
| STT·LLM 엔진 선택 저장 | 허용된 수신처에 서명하여 전송 |
| 웹훅 대기열 관리 | |

**회의 데이터 저장용 서버 DB는 두지 않는다.** 서버는 요청 처리에 필요한 데이터를 일시적으로 다루고, 제품의 영구 보관본은 브라우저에 저장한다. 요청 본문을 서버 로그·오류 추적 도구·캐시에 남기지 않는다.

로컬 녹음·메모·기존 회의 조회는 인터넷이 끊겨도 사용할 수 있도록 구성한다. AssemblyAI·OpenAI·웹훅 발송에는 인터넷 연결이 필요하다. Whisper·Ollama만 사용하는 경우 해당 AI 단계는 로컬 엔진 연결만으로 진행할 수 있다.

### 5.3 주요 서버 API

| API | 입력 | 출력·역할 |
|---|---|---|
| `GET /api/status` | 없음 | API 설정 여부, 연결 상태. 비밀값 제외 |
| `POST /api/transcriptions` | 음성, 요청 ID, 언어 | 업로드·전사 요청 후 전사 ID 반환 |
| `GET /api/transcriptions/:id` | 전사 ID | 처리 상태 또는 전사 결과 |
| `DELETE /api/transcriptions/:id` | 전사 ID | 제공업체 삭제 요청 결과 |
| `POST /api/generations` | 생성 종류, 입력 버전, 원문·메모, 프롬프트 | 검증된 요약 또는 상세 회의록 |
| `POST /api/webhooks/test` | 등록된 수신처 ID | 샘플 발송 결과 |
| `POST /api/webhooks/send` | 이벤트 ID, 확정 데이터 | 실제 발송 결과 |

회의 목록 조회·수정은 IndexedDB에서 처리하므로 별도의 `/api/meetings` 서버 저장 API를 만들지 않는다.

대용량 음성은 가능한 한 스트리밍 중계를 사용하고 전체 파일을 여러 번 메모리에 복제하지 않는다. Next.js Route Handler는 Web Streams 기반 응답 처리를 지원하며, 실제 배포 환경의 요청 크기·시간 제한도 별도로 검증해야 한다. 

### 5.4 저장·중복 실행·재시도 원칙

음성은 `localStorage`가 아니라 IndexedDB에 저장한다. `localStorage`는 대용량 음성 보관에 적합한 저장 공간이 아니며, 브라우저 저장 한도 초과 오류에 대한 별도 처리가 필요하다. 

한 번에 녹음 1건, AI 처리 흐름 1건만 실행한다. 여러 탭이 열려도 동일 작업이 중복 실행되지 않도록 작업 소유권을 관리한다.

명확한 요청 거절이나 일시적 오류와, 요청 성공 여부를 알 수 없는 네트워크 단절을 구분한다. 특히 비용이 발생하는 생성 요청은 성공 여부가 불명확한 상태에서 무조건 새 요청을 반복하지 않는다.

**제공업체 보관·삭제**

AssemblyAI를 사용한 경우, 결과를 로컬에 정상 저장한 뒤 전사 삭제 요청을 수행하고 성공·실패를 기록한다. 업로드 음성과 전사 결과의 보관·삭제 정책은 동일하지 않으므로, 전사 삭제 요청 성공을 모든 외부 사본의 즉시 삭제로 표시하지 않는다. Whisper(로컬) 실행에는 외부 전사 삭제 요청이 없다.

OpenAI 요청에는 `store: false`를 적용한다. 다만 이 설정만으로 모든 운영 로그까지 포함한 무보관이 보장되는 것은 아니다. 제공업체의 보관 정책과 별도 데이터 통제 조건을 확인해야 한다. Ollama(로컬) 실행에는 OpenAI 보관 정책이 적용되지 않는다. 

로컬 회의를 삭제해도 이미 사용자가 내보낸 파일이나 웹훅 수신처의 복사본은 회수되지 않는다. 외부 삭제가 대기 중이면 필요한 전사 ID와 삭제 상태만 별도로 남기고, 회의 본문은 보존하지 않는다.

실제 업무 도입 전에는 참석자 안내 방식, 사내 기밀정보 처리, 외부 AI 이용 조건, 개인정보 관련 검토를 완료해야 한다. 화면의 확인 체크만으로 이러한 검토가 끝난 것으로 취급하지 않는다.

### 7.1.1 화면별 Acceptance Criteria

아래 AC는 정상 흐름과 오류·취소 흐름을 함께 검증한다. 기존 기능 표의 완료·검증 기준은 모두 유지한다. 각 테스트 결과에는 화면 ID, AC ID, 연결 요구사항 ID, 입력 조건, 실제 결과와 증거를 기록한다.

#### SCR-01 회의 목록

- SCR01-AC01 (DATA-01): [새 회의] 또는 빈 화면의 시작 버튼을 선택하면 SCR-02 **생성 화면**(`/meetings/new`)이 열리고 아직 녹음·회의 저장은 시작되지 않는다.
- SCR01-AC02 (DATA-01): 회의 일시 최신순이 기본이며 오래된 순 선택 시 순서가 반전된다. 카드 상태는 3.2의 현재 상태와 일치한다.
- SCR01-AC03 (DATA-02~03): 검색·기간·상태·확정 필터를 동시에 적용할 수 있고 전체 초기화 시 조건과 결과가 복구된다.
- SCR01-AC04 (DATA-07): 삭제 취소는 데이터를 유지하며, 삭제 확인 후 목록·상세에서 해당 회의의 로컬 데이터에 접근할 수 없다. 외부 삭제 추적의 최소 정보는 6.2를 따른다.
- SCR01-AC05 (NFR-01): 회의 1,000건·검색 텍스트 각 5,000자 조건에서 목록 조회·검색 P95 500ms 이하를 검증하고 음성 Blob은 목록 조회에 로드하지 않는다.
- SCR01-AC06 (DATA-01~03): 최초 빈 화면과 검색 결과 없음 문구·주요 버튼이 구별된다.
- SCR01-AC07 (DATA-06): 더보기 내보내기와 백업 경로가 연결되고 회의별 백업을 복원해 본문·버전·음성 무결성이 유지된다.

#### SCR-02 새 회의·녹음

- SCR02-AC01 (REC-01): 마이크 권한 거부·장치 없음 상태에서는 녹음이 시작되지 않으며 원인과 재시도 경로가 보인다.
- SCR02-AC02 (REC-02): 녹음 시작 연속 클릭 및 두 탭 동작으로 녹음 인스턴스가 중복 생성되지 않는다.
- SCR02-AC03 (NOTE-02): 녹음 중 메모에는 실제 오디오 시점이 저장되고 녹음 전·후 메모에는 임의 시점을 붙이지 않는다.
- SCR02-AC04 (REC-02~03): 일시정지 시간은 표시 길이와 메모 타임라인에서 제외되며 재개·종료 버튼이 상태에 맞는다.
- SCR02-AC05 (SEC-01·05): 음성 저장 후 동의 미선택·취소·[음성만 저장]에서는 선택한 클라우드 STT·LLM에 대한 요청이 0건이다. 자동 생성 설정 ON이어도 동일하다. Whisper·Ollama만 선택된 경우에도 확인 없이 처리를 시작하지 않는다.
- SCR02-AC06 (DATA-01): 제목 미입력은 자동 제목, 유효한 일시는 시간대 포함 저장, 제한 초과 입력은 필드 오류로 처리한다. `[회의 시작]` 전에 목록·취소로 나가면 회의가 저장되지 않는다. `[회의 시작]` 중복 클릭은 회의 1건만 만든다.
- SCR02-AC07 (REC-04·07, NOTE-03·05): 저장 완료 표시 후 새로고침하면 저장된 메모가 복원된다. 저장 실패는 성공으로 표시하지 않고 마지막 저장 시점과 재시도·다운로드를 제공한다.
- SCR02-AC08 (REC-05): 110분 경고·120분 종료를 검증하며 200MiB 초과 파일은 AI 업로드가 차단되고 원본 저장 경로가 남는다.
- SCR02-AC09 (SEC-01·05, NOTE-04, AI-09): 생성 선택 후 동의·입력 스냅샷이 기록되고 AI 반영 해제 메모는 전송되지 않는다. 새 실행이나 입력 변경에는 새 확인이 필요하다.
- SCR02-AC10 (REC-06, DATA-04): [음성만 저장] 후 SCR-04에 원본 재생·메모·AI 생성 진입이 보이고 ‘검토 완료’나 ‘확정됨’으로 오표시하지 않는다.

#### SCR-03 AI 처리

- SCR03-AC01 (AI-01): 각 단계·경과 시간이 실제 작업 상태와 일치하고 기존 전사 재사용은 업로드 실행으로 표시하지 않는다.
- SCR03-AC02 (AI-01): 전사·LLM 생성에 임의 퍼센트가 없으며, AssemblyAI 업로드 퍼센트는 측정된 바이트로 계산한다. Whisper 로컬 입력에는 가짜 업로드 퍼센트를 표시하지 않는다.
- SCR03-AC03 (AI-08, NFR-05): 요약 성공·상세 실패 시 요약과 기존 확정본을 보존하고 상세만 재시도한다.
- SCR03-AC04 (AI-05): 새로고침 후 전사 ID가 있으면 기존 작업을 조회하며 새 전사를 중복 요청하지 않는다.
- SCR03-AC05 (AI-09~10): 생성 중 입력 변경은 진행 실행의 스냅샷을 바꾸지 않으며 완료 결과에 입력 변경 경고를 표시한다.
- SCR03-AC06 (AI-12): 무음·빈 전사·거절·응답 중단·응답 유실에 맞는 안내와 다음 행동을 제공하고 빈 회의록을 성공으로 저장하지 않는다.
- SCR03-AC07 (AI-08): 완료 시 해당 처리 화면에 있는 경우만 검토 화면으로 이동하며 다른 화면의 편집을 중단시키지 않는다.

#### SCR-04 회의 결과·검토

- SCR04-AC01 (REC-06, AI-07): 유효한 전사 근거 선택 시 해당 원문을 표시하고 오디오를 source.startTime으로 이동한다. 재생 후 구간 끝+3초 또는 음성 끝에서 정지하고 계속 재생할 수 있다.
- SCR04-AC02 (DATA-04): 사용자 편집·자동 저장 후 AI 생성 원본은 그대로 조회 가능하다.
- SCR04-AC03 (AI-10): 생성 입력 전사·AI 반영 메모 수정 시 최신 여부 경고를 표시하고 입력이 변하지 않은 제외 메모 수정에는 경고를 추가하지 않는다.
- SCR04-AC04 (DATA-05, AI-08): 재생성 성공·실패 모두 기존 사용자 수정본과 확정본을 덮어쓰지 않는다.
- SCR04-AC05 (DATA-05): 확정 시 새 보존 버전을 만들며 미해결 항목 수 경고와 해당 내용이 유지된다.
- SCR04-AC06 (NOTE-02, AI-07): 메모 근거는 사용자 메모로 구분하고 시점 없는 메모에는 오디오 이동을 제공하지 않는다. 음성 누락·손상·잘못된 근거는 오류로 안내한다.
- SCR04-AC07 (AI-03~04): 화자명 수정은 전사 수정본과 이후 생성 입력에 반영되며 원래 라벨·전사 원문은 보존된다.
- SCR04-AC08 (DATA-05, WH-01): 확정 이후 편집·이전 버전 복원은 새 초안으로 표시하고 자동 확정·전송하지 않는다. 이전 확정·전송 이력은 유지한다.
- SCR04-AC09 (AI-06~07): 원문에 없는 담당자·기한은 미정이며 상충 정보는 확인 필요로 남는다. 부분 생성·결과 없음은 정상 완료 결과와 구별된다.
- SCR04-AC10 (DATA-06): TXT·Markdown 내보내기는 선택한 결과 버전과 일치하고 회의별 ZIP 백업·복원이 가능하다.

#### SCR-05 설정

- SCR05-AC01 (SET-01~06): 요약용·상세용 프롬프트를 독립 저장·복원하며 다른 프롬프트가 바뀌지 않는다.
- SCR05-AC02 (SET-01~06): 20자 미만·4,000자 초과 입력은 저장 불가이고 글자 수·오류를 표시한다.
- SCR05-AC03 (SEC-02): 설정 UI·응답·브라우저 저장소에 실제 API 키가 없고 엔진 선택·연결 상태만 표시한다.
- SCR05-AC04 (SET-01~08): 미저장 변경이 있으면 닫기·외부 클릭·Escape 모두 폐기 확인을 거치며 취소하면 편집 내용이 유지된다.
- SCR05-AC05 (SET-01~06, SEC-05): 샘플 시험 생성은 선택한 LLM에 맞는 비용·호출 확인 후 고정 샘플만 사용하고 실제 회의 데이터를 포함하지 않는다.
- SCR05-AC06 (DATA-06, SEC-08): 저장 용량은 추정임을 표시하고 로컬 저장 한계·백업 안내·복원 경로가 제공된다.
- SCR05-AC07 (SEC-01): 자동 생성 안내 설정을 변경해도 실행별 처리·외부 전송 동의를 생략하지 않는다. 키보드로 대화상자를 조작하고 닫으면 호출 위치에 초점을 복원한다.
- SCR05-AC08 (SET-07~08): STT는 Whisper|AssemblyAI, LLM은 Ollama|OpenAI 중 하나를 저장·복원하며, 이후 AI 실행과 동의 안내에 선택한 엔진이 반영된다. 연결 불가 엔진으로는 생성을 시작하지 않는다.

#### SCR-06 외부 연동

- SCR06-AC01 (WH-01~02): 초기 연동은 OFF이며 전사문·메모 기본 제외, 음성 전송 미지원이다. 확정본 없이는 실제 발송할 수 없다.
- SCR06-AC02 (WH-03): 시험 발송 확인 후 실제 회의 데이터 없는 샘플만 보내며 성공·실패·HTTP 상태·응답 시간을 표시한다.
- SCR06-AC03 (WH-01·02·07): 발송 전 대상·확정 버전·항목을 확인하고 미리보기와 동일한 스냅샷을 보낸다. [확정만] 선택은 발송 이벤트를 만들지 않는다.
- SCR06-AC04 (WH-04): 이벤트·버전·대상·시도별 시각·응답·다음 재시도 시각이 이력과 실제 요청에 일치한다.
- SCR06-AC05 (WH-05~06): 재시도는 동일 이벤트 ID·동일 본문을 유지하고 최대 횟수·간격·HTTP 분류를 준수한다. 웹훅 실패로 확정본은 변경되지 않는다.
- SCR06-AC06 (WH-07): 미발송 대기·예약 재시도 취소 후 새 발송을 하지 않는다. 이미 전송 중이거나 수신된 요청을 회수했다고 표시하지 않는다.
- SCR06-AC07 (WH-04~05): 앱 종료 중 발송 성공으로 표시하지 않고 재실행 후 대기열을 복원한다. 전송 성공 배지는 현재 확정 버전의 성공에만 적용한다.
- SCR06-AC08 (WH-02·07, SEC-05): 설정 변경으로 기존 대기 본문이 바뀌지 않으며 새 발송은 변경된 항목을 다시 확인한다. 제외 항목·음성·비밀키는 실제 요청에 포함되지 않는다.

### 7.2 AI 품질 평가

평가 세트는 한국어 회의 30건 이상으로 구성한다. 짧은 회의, 60분 이상 회의, 여러 화자, 숫자·날짜가 많은 회의, 소음이 있는 회의, 결정이 없는 회의를 포함한다.

전사 품질과 회의록 품질은 분리해 평가한다. 전사 결과가 틀린 상황에서 요약만 자연스럽다는 이유로 통과시키지 않는다.

정답 회의록은 검토자 2명이 독립 작성한 후 차이를 조정한다. 결정사항·후속 업무의 누락, 원문에 없는 확정 내용, 담당자·기한의 오류를 각각 집계한다.

### 7.3 출시 차단 조건

아래 조건 중 하나라도 해당하면 출시를 보류한다.

- 복구 불가능한 데이터 손실, API 키 노출, 무단 외부 전송 결함이 남아 있다.
- 평가 세트에서 원문에 없는 중대한 결정·담당자·기한이 생성된다.
- P0 요구사항에 대응하는 테스트가 없거나 필수 테스트가 실패한다.
- 사용자 안내와 실제 저장·전송·삭제 동작이 다르다.

버그가 없다는 일반적인 선언보다, **화면 ID → 요구사항 ID → AC ID → 구현 항목 → 테스트 결과**의 연결을 출시 근거로 사용한다.
